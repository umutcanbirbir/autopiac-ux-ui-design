| --- | --- |

## Navigation and Layout

The review covered **10** main screens and **24** links between actions or Review sections. All inspected links had destinations. The mobile main path reaches Start → Vehicle Details → Equipment & Condition → Photos → Price & Description → Review → Success, as well as the two validation example screens. The desktop Vehicle Details frame is a separate standalone responsive variant and is **not a destination from the mobile first screen**; its own continue action is linked.

No major frame-boundary problems were found in the inspected layouts. The design should still be checked at different screen sizes.

## Color Contrast Checks

Computed WCAG contrast ratios for key color pairs:

| Foreground | Background | Contrast ratio |
| --- | --- | ---: |
| \`#1F1F1F\` primary text | \`#FFD400\` primary yellow | **11.51:1** |
| \`#6D675C\` secondary text | \`#FFF7D8\` pale yellow | **5.22:1** |
| \`#775700\` gold text | \`#FFF0A8\` yellow soft | **5.81:1** |
| \`#B42331\` error text | \`#FFFFFF\` white | **6.51:1** |

These tested text-color pairs exceed the WCAG 2.2 AA 4.5:1 normal-text target. Full keyboard and accessibility checks remain separate tasks.

## Remaining Work

1. **Figma forms are prototypes**: the 16 equipment options and front-left fender condition are interactive components; text entry, saved listing data, actual image upload and database publication remain unimplemented.
2. **Review→Edit is clickable, but field edits are not stored.** The user normally proceeds through the flow again to reach Review. A conditional “Save and return to Review” behavior is a future prototype improvement.
3. **Further error states** — upload failure, network submission failure, one-active-private-listing limit — are documented requirements, not yet fully modeled in the revised Figma flow.
4. **A realistic task test and post-change participant retest** are still required to substantiate improvements; see [Homework 08](../../homework/08/README.md), [Homework 09](../../homework/09/README.md) and [R01 research interview](interview-r01.md).
5. **Accessibility verification** beyond sampled color pairs, such as keyboard access, screen reader labels, interactive focus, target sizes and motion, is outstanding.
6. The body panel state selector currently represents **one example panel**, not a complete interactive 13-panel condition diagram.
7. A **final professor-facing presentation** and any lecturer-specific submission checks remain outstanding.

## Summary

The revised design now has a consistent mobile-first visual style, clear navigation and two example error states. It is ready for further feedback on the newest equipment and condition section. The Figma text fields and photo placeholders remain visual examples; equipment and one damage-panel selector use interactive component states.

## Follow-Up Component Update — 22 November 2026

After this initial layout review, the Equipment & Condition screen was updated with a reusable [interactive Equipment Toggle component](https://www.figma.com/design/Po5hpum1mNJ7VnfVc0FTmC?node-id=2040-9). Its two On/Off variants use click-to-change interactions, and all 16 equipment choices now have independent component instances. The original visual search placeholder was removed. The click reaction targets and variant text preservation were checked in Figma; Present-mode participant testing of the new interactions remains open. Other form elements and the Review summary are not connected to saved listing data.

The next update introduced an [interactive Body Panel Condition component](https://www.figma.com/design/Po5hpum1mNJ7VnfVc0FTmC?node-id=2044-34), with five mutually exclusive variants for the *Front-left fender*. All 20 transitions between different states were structurally verified; the selected label matched the active option for every state. A participant has not yet confirmed this particular interaction in Present mode. The design still covers only one example panel rather than all 13 planned panels.

## Accessibility Update — 22 November 2026

A new [WCAG 2.2 AA design-level accessibility review](accessibility-review-2026-11-22.md) inspected ten current Figma frames, 204 text layers and 44 prototype interaction hit boxes. Nine essential form outlines were darkened to exceed 3:1 contrast against white; small equipment, damage-state and photo labels were enlarged. Prototype hit boxes measured at least 36 px in their smallest dimension. The report separates design-level findings from keyboard, screen-reader, resize/reflow and real-form behavior that still requires a functioning interface.

This update supersedes the older references above to **untested target sizes** and to a **pending prototype retest**: three people have now given positive feedback on the updated equipment/damage components. It does not supersede the remaining functional accessibility and saved-data limitations.

## Navigation / Layout Sanity Check

A structural Figma inspection found **10** top-level current-design screens, **24** linked primary actions / review section controls and **zero** checked actions with missing destinations. The mobile main path reaches Start → Vehicle Details → Equipment & Condition → Photos → Price & Description → Review → Success, as well as the two validation example screens. The desktop Vehicle Details frame is a separate standalone responsive variant and is **not a destination from the mobile first screen**; its own continue action is linked.

The inspected screens' **top-level children do not overflow their frames** based on Figma x/y/width/height properties. This is not a substitute for testing all device renderers or zoom levels.

## Sample Color Contrast Checks

Computed WCAG contrast ratios for key color pairs:

| Foreground | Background | Contrast ratio |
| --- | --- | ---: |
| \`#1F1F1F\` primary text | \`#FFD400\` primary yellow | **11.51:1** |
| \`#6D675C\` secondary text | \`#FFF7D8\` pale yellow | **5.22:1** |
| \`#775700\` gold text | \`#FFF0A8\` yellow soft | **5.81:1** |
| \`#B42331\` error text | \`#FFFFFF\` white | **6.51:1** |

These particular text-color pairs exceed the WCAG 2.2 AA **4.5:1 normal-text threshold**. They are spot checks, **not** a claim of full WCAG 2.2 conformance or a measured result for every style/state.

## Still Open — Do Not Overclaim

1. **Figma controls are static**: no actual text entry, saved selection, uploaded image or database publication is implemented. Checkbox/radio marks and thumbnails are design examples.
2. **Review→Edit is clickable, but field edits are not stored.** The user normally proceeds through the flow again to reach Review. A conditional “Save and return to Review” behavior is a future prototype improvement.
3. **Further error states** — upload failure, network submission failure, one-active-private-listing limit — are documented requirements, not yet fully modeled in the revised Figma flow.
4. **A realistic task test and post-change participant retest** are still required to substantiate improvements; see [Homework 08](../../homework/08/README.md), [Homework 09](../../homework/09/README.md) and [R01 research interview](interview-r01.md).
5. **Accessibility verification** beyond sampled color pairs, such as keyboard access, screen reader labels, interactive focus, target sizes and motion, is outstanding.
6. The body panel state selector currently represents **one example panel**, not a complete interactive 13-panel condition diagram.
7. A **final professor-facing presentation** and any lecturer-specific submission checks remain outstanding.

## Conclusion

After QA, the revised AutoPiac design is internally consistent as a **mobile-first, clickable, yellow-and-white Figma prototype**. The main navigation, review routes, two error examples and visual hierarchy can be demonstrated. It remains a **static UX/UI design deliverable**, not a live vehicle marketplace or verified end-to-end form experience.
